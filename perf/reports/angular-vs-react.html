6. Findings

  1. Budget misses. Angular home CLS 0.131; Angular article CLS 0.131. LCP and TBT still sit under the Google “good” lines on both apps.
  2. Home LCP median is 208 ms on Angular and 216 ms on React (+4% after the migration). Login LCP winner is Angular. Article LCP winner is Angular.
  3. Home TBT median is 0 ms on Angular and 0 ms on React. Article TBT is a tie at 0 ms on this unthrottled laptop.
  4. Total JS is 417.0 kB (134.5 kB gzip) on Angular across 22 files, and 452.2 kB (145.9 kB gzip) on React across 1 file (+8%, Angular smaller). Largest chunk is chunk-JC6VLHRF.js at 278.3 kB vs assets/index-BgRXxivE.js at 452.2 kB (+62%).
  5. Angular lazy-loads routes with loadComponent, so the lab downloads extra chunks after the first paint. React’s production build is a single JS chunk. That is the main structural bundle difference, not a k6 result.
  6. k6 smoke against the local Bun mock passed with p95 488 µs. That number is loopback JSON, not an Angular vs React delta, and not api.realworld.show capacity.

7. Conclusions and what to improve

  1. React improved CLS on home (0.072 vs Angular 0.131) and article (0.032 vs 0.131). Angular still misses the 0.1 “good” line. Give the home banner logo and article hero images width/height (or a reserved min-height) so Ionicons and webfonts cannot shove the feed. LCP and TBT are not the problem on this host.
  2. React ships 35.2 kB more JS uncompressed than Angular. Split React routes (home, auth, article) the way Angular already does with loadComponent, and keep the 500 kB largest-chunk lock.
  3. Home LCP is within 8 ms across the two apps. CDN fonts and icons still sit on the critical path for both. They are the first lever if field LCP is worse than this lab.
  4. Do not use the k6 mock p95 as an API SLO. Re-run PROFILE=load against a backend you own before talking about capacity. Never aim k6 at api.realworld.show.
